# Vision — TechProjectForge

## Problem

Technical projects accumulate truth in repos (ICD, ARCHITECTURE, requirements, design notes, code, tests, CI) while books and guides are written separately and drift. HerbalBookForge covers herbal nonfiction; it is the wrong domain model for engineering handbooks.

## Goal

A reusable **nonfiction engine** that authors technical project books by citing project artifacts, with the same anti-slop bar as fiction/herbal tools: readable, specific, human-relatable prose that a domain expert can lightly edit—not a dump of AI-pattern filler.

## Book shapes (examples)

- Field guide / operator handbook  
- Architecture deep-dive  
- Build log → polished book  
- Multi-repo program series (shared SeriesBible, per-book BookState)

## Success

- Chapters cite EvidencePack / ReferenceDoc ids from the repo  
- Promote to L1/L2 only after quality gate  
- Works for **any** technical project (firmware, cloud, agent platforms, farm hardware)—not one vertical hard-coded  
- Default path: paste-bridge (Bot / Chat / Copilot); no extra xAI console key
